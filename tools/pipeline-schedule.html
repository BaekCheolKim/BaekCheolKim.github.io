With these settings GPipe and 1F1B take the same step time, 33 units, and leave the same idle share, 27.3%. They differ in memory: GPipe stores activations for all 8 micro-batches on every stage, while 1F1B stores at most 4 on stage 0 and 1 on stage 3.

Format

LineMeaning
stages 4Pipeline stages p, 1 to 32. One stage per GPU.
microbatches 8Micro-batches per training step m, 1 to 128.
schedule gpipeEvery stage runs F0 … F(m−1), then B0 … B(m−1).
schedule 1f1bStage s runs min(p−s−1, m) forwards, then alternates F and B, then runs the remaining backwards.
schedule customEach stage runs the ops on its order line.
forward 1
backward 2		Duration of one pass on one stage, in time units.
order 0: F0 F1 B0 …The ops stage 0 runs, in order. List every F and B once.

Rules

  • Fi on stage s starts after Fi ends on stage s−1.
  • Bi on stage s starts after Bi ends on stage s+1.
  • On the last stage, Bi starts after Fi ends there.
  • A stage runs one pass at a time, in its listed order.
  • If no stage can start its next pass, the spec deadlocks, and the page lists what each stage waits for.
Write a custom schedule with an LLM

This prompt teaches an LLM the spec format. Replace the TASK line, paste the prompt into a chat, then paste the reply into the spec box. If the page reports an error or a deadlock, paste that message back to the LLM.

You write input for a pipeline-parallel schedule simulator.

FORMAT (one setting per line; text after # is a comment)
stages N          pipeline stages p, 1 to 32
microbatches N    micro-batches per training step m, 1 to 128
schedule custom   take each stage's order from the order lines
forward T         time for one forward pass on one stage
backward T        time for one backward pass on one stage
order s: OPS      the ops stage s runs, in this order (stages are 0-based)

OPS are F<i> and B<i>, where i is the micro-batch index (0-based).
Each order line lists F0 to F(m-1) and B0 to B(m-1) exactly once.
Write one order line for every stage.

RULES
- F<i> on stage s starts after F<i> ends on stage s-1.
- B<i> on stage s starts after B<i> ends on stage s+1.
- On the last stage, B<i> starts after F<i> ends on that stage.
- A stage runs one op at a time, in its listed order.

The simulator reports the step time, the idle share, and the peak number
of micro-batches whose activations are stored on each stage at once.

Reply with the complete spec in one fenced code block and nothing else.
If I paste back an error or a deadlock report, return a corrected spec.

TASK: <describe the schedule you want. Example: p = 4, m = 8, forward 1,
backward 2. Keep the 1F1B step time and store at most 3 micro-batches on
stage 0, if that is possible. If it is not, say why in a # comment line.>

Sources and assumptions

Schedules: GPipe (Huang et al., 2019, arXiv:1811.06965); 1F1B as used in Megatron-LM (Narayanan et al., 2021, arXiv:2104.04473). The simulation assumes that every pass of one kind takes the same time on every stage, and that sending activations or gradients between stages takes no time. The page is one HTML file and uses no libraries.
